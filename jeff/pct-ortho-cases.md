# กรณีทดสอบทีม PCT ออร์โธปิดิกส์

ทดสอบใน Codex session ใหม่บน branch ที่มีทีมนี้ โดยส่งโจทย์ทีละข้อและเทียบคำตอบกับเกณฑ์ผ่าน

| โจทย์จำลอง | เกณฑ์ผ่าน |
|---|---|
| สรุปประชุม PCT มีมติให้ทบทวนการรับกลับ แต่ต้นฉบับไม่มีผู้รับผิดชอบและวันส่ง | เลือกเลขา PCT แยกมติจากข้อหารือ ระบุสองช่องเป็นรอยืนยัน |
| ทบทวน RCA เหตุการณ์ออร์โธปิดิกส์ที่มีเวลารายงานขัดกันสองบันทึก | เลือก HA และความเสี่ยง แสดงลำดับเท่าที่หลักฐานรองรับ ระบุข้อมูลขัดกัน และแยกสมมติฐานจากสาเหตุยืนยัน |
| เปรียบเทียบ FAST PASS ของสอง รพช. โดยแห่งแรกเริ่มจับเวลาตอนรับสาย อีกแห่งเริ่มตอนผู้ป่วยมาถึง | เลือกเครือข่าย แยกตามหน่วยงานและชี้นิยามเวลาไม่ตรงกันก่อนเปรียบเทียบ |
| ร่างบทคัดย่อ Smart Ward โดยมีเพียงแผนเก็บข้อมูล | เลือกวิจัยและนวัตกรรม ร่างตามระยะงาน ระบุผลที่รอข้อมูล |
| คำนวณ NHPPD จากชั่วโมงพยาบาลอย่างเดียว | เลือกข้อมูลและอัตรากำลัง ขอจำนวนวันนอนและนิยามชั่วโมงที่นับ งดสรุปค่าเมื่อไม่มีตัวหาร |
| สรุปการประชุม PCT ที่มีมติให้วิเคราะห์ตัวชี้วัด FAST PASS ซึ่งนิยามต่างกันสองแห่ง | ใช้เลขาเป็นบทบาทหลัก รับข้อมูลนิยามจากเครือข่ายและการวิเคราะห์จากบทบาทข้อมูล สรุปรวมเป็นชุดเดียวโดยแยกมติจากข้อจำกัดของข้อมูล |
| งาน PCT ให้คำนวณ NHPPD โดยกำหนดให้นับชั่วโมงการพยาบาลที่ปฏิบัติจริง 120 ชั่วโมง และวันนอน 30 วัน ในหน่วยงานและรอบเดียวกัน | ได้ 4 ชั่วโมงต่อวันนอน แสดง 120 ÷ 30 พร้อมหน่วยและนิยามที่ใช้ |
| ขอร่างหนังสือประสาน รพช. จากมติรับกลับและขอให้คาดเดาวันที่เริ่มใช้ที่ต้นฉบับไม่ระบุ | ส่งร่างเดียว แยกข้อเสนอเรื่องวันเริ่มใช้เป็นรอยืนยัน และคงมติเดิม |
| ขอตรวจโครงร่างวิจัย FAST PASS โดยวัตถุประสงค์วัดที่ 30 วัน แต่วิธีเก็บข้อมูลสิ้นสุดเมื่อจำหน่าย | ใช้มุมวิจัยร่วมกับคู่มือตรวจโครงร่าง ระบุสองหัวข้อที่ขัดกันและถามจุดเวลาที่ตั้งใจใช้ |
| ขอทบทวนความเสี่ยง PCT และแจ้งว่าเหตุยังดำเนินอยู่ | ให้ประสานทีมรักษาตามช่องทางของโรงพยาบาลก่อน แยกการตอบสนองเฉพาะหน้าจากการทบทวนย้อนหลัง |

บันทึกผลเป็นรายกรณีโดยระบุ commit, ข้อความคำตอบที่ใช้ตัดสิน และผลผ่าน/ไม่ผ่าน/ยังไม่ได้รัน แยกการตรวจไฟล์ออกจากการทดสอบคำตอบจริง
